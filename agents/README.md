# AI Week 2단계 — 에이전트 실행 규약

이 폴더의 파일 하나가 에이전트 하나다. 각 파일은 그 에이전트의 **시스템 프롬프트 전문**이며, 실행할 때 그대로 넣는다. 사람이 손으로 요약하거나 합치지 않는다.

## 왜 파일을 나누는가

모델 하나에게 "네 관점으로 봐 줘"라고 하면 네 명을 흉내 낸 한 명이 나온다. 같은 머리에서 나온 이견은 이견이 아니다. 관점이 실제로 다르려면 **정체성·조사 절차·판단 기준·편향이 다른 프롬프트**가 따로 있어야 하고, 서로의 결과를 보지 못한 채 각자 조사해야 한다.

## 실행 순서

```
0층  후보군    00_후보군.md        → pool.json          (규칙 기반, 판단 없음)
1층  관찰      01~04 (병렬·격리)   → obs_가치.json 등 4개
2층  종합      05_종합.md          → synthesis.json
3층  구성      06_구성.md          → basket.json  → picks.json 회차 항목
```

### 1층의 격리 규칙 (가장 중요)

- 네 관찰 에이전트는 **같은 pool.json**을 받는다. 그 외에 받는 것은 자기 프롬프트뿐이다.
- **서로의 출력을 절대 보지 않는다.** 병렬로 띄우고, 한 에이전트의 결과를 다른 에이전트 입력에 넣지 않는다.
- 각자 **웹에서 직접** 가격과 뉴스를 확인한다. 사람이 미리 정리한 요약을 주지 않는다. 같은 사실을 넷이 각자 찾아야 "넷이 확인했다"가 된다.
- 어느 에이전트도 종목을 소유하지 않는다. 후보군 **전체**에 대해 소견을 낸다.
- 어느 에이전트도 심판이 아니다. '위험' 포함. 남을 떨어뜨릴 권한이 없다.

### 2층·3층

- 종합은 네 출력을 **모두** 읽고, 갈린 지점을 **지우지 않고** 기록한다. 평균내지 않는다.
- 구성은 다섯을 **하나의 묶음**으로 짠다. 개별 점수 상위 5개가 아니다. 뺀 종목의 이유는 "묶음 차원"에서 쓴다.

## 공통 출력 형식 (1층)

각 관찰 에이전트는 아래 JSON 하나만 출력한다. 산문 보고서를 쓰지 않는다.

```json
{
  "agent": "가치",
  "basis_date": "YYYY-MM-DD",
  "opinions": [
    {
      "code": "005930",
      "name": "삼성전자",
      "close": 249000,
      "close_source": "https://…",
      "stance": "편입 | 보류 | 반대",
      "confidence": 0.0,
      "opinion": "이 관점에서 본 한두 문장. 남의 관점을 빌리지 않는다.",
      "evidence": [
        { "fact": "숫자나 사실 하나", "source": "https://…", "date": "YYYY-MM-DD" }
      ],
      "what_would_change_my_mind": "무엇이 확인되면 입장을 바꾸는가"
    }
  ],
  "pool_note": "후보군 전체를 보고 든 생각 한두 문장 (선택)"
}
```

- `close`는 **기준일 종가**. 반드시 출처 URL을 단다. 찾지 못하면 `null`로 두고 `opinion`에 그렇게 쓴다. 추정하지 않는다.
- `stance`는 셋 중 하나. '보류'는 도망이 아니라 "내 관점의 재료가 부족하다"는 뜻이고, 무엇이 부족한지 적어야 한다.
- `confidence`는 0~1. 전부 0.5로 채우면 정보가 없다. 차이를 내라.
- `evidence`는 최소 2개. 출처 없는 사실은 사실이 아니다.

## 하지 말 것 (모든 에이전트 공통)

- 다른 관점의 언어를 쓰지 말 것. 가치 에이전트가 "수급이 좋다"고 쓰면 실패다.
- 틀리지 않으려고 전부 '보류'로 쓰지 말 것. 틀린 기록이 남는 것이 이 실험이다.
- 기준일 이후의 가격·뉴스를 쓰지 말 것. 기준일 종가 시점에서 알 수 있던 것만.
- 사람이 정한 결론에 맞추지 말 것. 이 프롬프트를 쓴 사람도 결과를 모른다.
